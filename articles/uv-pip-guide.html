使用 uv pip 管理项目环境：
Python 开发新选择

2026-01-06 Python 工具

核心逻辑

uv 常见有两条路：

  • 项目模式：用 uv init / uv add / uv sync 配合 pyproject.toml 管理依赖，适合需要打包、共享的项目。
  • pip 接口：用 uv pip install / uv pip freeze / uv pip sync 直接操作虚拟环境，适合已经习惯 pip 和 requirements.txt 的项目。

实战里最常见的组合：.venv + requirements.txt + uv pip install / sync

一、安装 uv

1.1 在线一键脚本（最省事）

# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows PowerShell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 验证
uv --version

官方安装脚本不依赖系统 Python。uv 会把程序装到用户可执行目录，Unix 上通常是 ~/.local/bin，Windows 上通常是 %USERPROFILE%\.local\bin。

1.2 离线手动下载（内网 / 机器没 curl）

  1. 在能上网的电脑打开 https://github.com/astral-sh/uv/releases/latest，根据系统下载对应压缩包，例如
    • Windows 10+ 64bit → uv-x86_64-pc-windows-msvc.zip
    • Linux x86_64 → uv-x86_64-unknown-linux-gnu.tar.gz
    • macOS Apple Silicon → uv-aarch64-apple-darwin.tar.gz
  2. 解压后得到单文件 uv（或 uv.exe），把它放到系统 PATH 已包含的目录里，例如：
    • Windows：%USERPROFILE%\.local\bin\
    • Linux/macOS：~/.local/bin/ 或 /usr/local/bin/
  3. 终端执行 uv --version 验证。

装完后就能直接管理 Python 版本与虚拟环境。

# 让 uv 下载一个 3.12 系列的 Python
uv python install 3.12

# 建虚拟环境
uv venv --python 3.12

# 装包
uv pip install requests

# 运行脚本
uv run python your_script.py

如果本机已经有符合要求的 Python，uv 也会直接使用；没有的话，它会自动下载可用版本。

二、初始化：为项目创建 .venv 虚拟环境

2.1 在项目根目录

uv venv
# 或者指定 Python 版本
uv venv --python 3.12
# 也可以指定环境目录
uv venv --python 3.12 new_env

说明：

  • 默认会在当前目录创建 .venv，只对这个项目生效。
  • 后续用 uv pip 或 uv run 时，uv 会自动优先找到项目里的这个环境，不需要你手动 activate。

2.2 虚拟环境的本质

uv 创建的是一个隔离环境：第三方包装进 .venv，不会写进系统 Python 的 site-packages。

  • 如果直接执行 uv venv，uv 会使用当前可用的 Python 来创建环境；如果你想固定某个版本，直接加 --python 3.12 会更清楚。
  • 如果执行 uv venv --python 3.12，uv 会优先使用已安装或已管理的 3.12；如果没有，就自动下载再创建环境。
  • uv 管理的是“项目依赖 + 解释器引用”，不是把系统 Python 整个复制一份到 .venv 里。

三、安装和维护依赖（核心三件事）

3.1 首次安装依赖

直接用 uv pip install 往当前虚拟环境里装包：

uv pip install pymysql requests beautifulsoup4 neo4j
uv pip install -r requirements.txt
  • uv 会自动优先使用项目里的 .venv，通常不需要手动激活。

注意：uv pip install 只会把包装进当前虚拟环境的 site-packages，不会修改系统 Python 的安装目录。

也就是说：
虚拟环境是项目自己的仓库
系统 Python 是另一套仓库

删掉 .venv，项目依赖就跟着没了；系统 Python 本身不会被动到。

安装完成后可以测试一下：

uv run python -c "import pymysql, requests, bs4, neo4j; print('imports ok')"

这也是使用 uv 跑一小段代码的方式。

3.2 导出或更新 requirements.txt

当你对依赖比较满意时，可以把当前环境导出来：

uv pip freeze > requirements.txt

如果你想让环境和 requirements.txt 完全一致，通常用 uv pip sync requirements.txt 会比 install 更稳。

四、其他常用命令

4.1 查看 Python 版本

uv python list

4.2 查看 uv 管理的 Python 路径

uv python dir
uv python dir --bin

uv python install 3.12 安装的是 uv 管理的 Python 版本。Python 解释器和相关文件通常存放在 uv 的数据目录里，而可执行文件会放到用户的 PATH 目录中。

4.3 卸载某个 uv 管理的 Python

uv python uninstall 3.12

五、关于移动 .venv

如果你只是想把项目目录挪到别的位置，建议把 .venv 也一起带上，然后在新位置先跑一次 uv run 或 uv pip check 看环境是否正常。遇到解释器路径变化时，再让 uv 重新创建或修复环境会更稳妥。

如果你确实需要“可重定位”的虚拟环境，可以再单独研究 --relocatable / UV_VENV_RELOCATABLE，但这不是默认行为，所以文章里我不建议把它写成通用结论。
